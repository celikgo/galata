# Working in galata

Flight dynamics and control-law design in C++20. Trim, linearise, classify the modes,
evaluate frequency response and margins — with every number traceable to the routine that
produced it and to the document it was checked against.

**Read before changing anything:** `README.md`, `docs/CHARTER.md`, `docs/VERIFICATION.md`,
`docs/TESTING.md`, `docs/notes/phugoid-damping.md`, and the ADRs in `docs/adr/`.

## Build and test

vcpkg in manifest mode fetches Eigen, yaml-cpp and GoogleTest. `VCPKG_ROOT` must point at
a vcpkg checkout.

```bash
export VCPKG_ROOT=/path/to/vcpkg
cmake --preset dev
cmake --build --preset dev
ctest --preset dev            # the whole suite — this is the one command
```

One tier at a time by ctest **label**: `ctest --preset dev -L validation`. The labels are
`unit`, `property`, `integration`, `validation`, `determinism`, and they match the table in
`docs/TESTING.md`. Presets: `dev` locally; `ci-linux-gcc`, `ci-linux-clang` and `ci-macos` in
CI; `asan` for the sanitiser build. Linux (GCC and Clang) and macOS (AppleClang) are the
supported platforms — Windows was withdrawn, and no job builds or tests it.

## The five rules that decide most reviews

The charter has nine. These are the ones a change is most likely to break.

**1. Strict SI in the numerical core.** Metres, seconds, kilograms, newtons, newton-metres,
radians, radians per second, kelvin, pascals. Every public struct field carries its unit in a
trailing comment — `double airspeed_m_s = 0.0;  // m/s`. Degrees, feet, knots and Celsius
exist only in the UI layer and in file-format adapters, and they are converted by
`include/galata/units.hpp` and nowhere else. `scripts/check-si-boundary.sh` fails the build on
a conversion call *or a conversion factor written as a literal* inside `src/core`, `src/model`,
`src/numerics`, `src/trim`, `src/linearize`, `src/analyze`, `src/sim` and their headers. A
constant that legitimately looks like a conversion factor needs a `GALATA_SI_EXEMPT` comment on
the line saying what it actually is. See ADR-0003 and the `adding-an-aircraft-model` skill.

**2. A number without a traceable routine and a stated budget does not go in a document.**
Not in the README, not in a doc comment, not in a skill, not in an example write-up. A figure
about galata's own behaviour is measured at render time and referred to by name:
`docs/VERIFICATION.md` is generated by `tools/validation/report_main.cpp`, its prose carries
`{placeholders}`, and the generator **refuses to run** if a case note contains a value it also
computes. `docs/assets/modal-map.json` and `docs/assets/nt33a-fc1-run.json` are emitted by
`tools/social/` and `tools/report/`; the pictures and the report page are drawn from them.
CI regenerates all four and fails on drift. If you find yourself typing a number you just read
off a run, that is the mistake this rule exists for. See the
`validating-against-a-published-source` skill.

**3. Never widen a gate to make a number pass.** A deviation larger than its budget is
localised, published, and held by a *labelled* regression lock — it is not absorbed by a
tolerance. Two of these are load-bearing and must not be removed or relaxed:
`Nt33aHandAssembled.PhugoidDampingDiscrepancyDoesNotGrow` (galata is wrong) and
`DiskMarginSeiler2020.PublishedCriticalFrequencyDisagreesWithItsOwnPublishedPerturbation`
(the source is wrong). Both are two-sided: they fail if the disagreement *shrinks* too, so a
future fix is loud rather than silent.

**4. Determinism is a tested property, and it is easy to break by accident.** Same platform,
same bits. Fixed iteration counts in root-finders, never a tolerance-based early exit. No
`unordered_map` iteration reaching output. No `long double` in the numerical core. No
`-ffast-math`, no FMA contraction. Across platforms — Linux and macOS, the two supported — the
promise is agreement to a published bound, not bit-identity, because platform math libraries
disagree on `sin` in the last bits. Tier 2 compares every pair, which with two platforms is one
comparison; the bound itself is unchanged. See ADR-0004 and the `preserving-determinism` skill.

**5. Nothing is documented before it works, and every physics file cites its source.**
`scripts/check-doc-references.sh` holds the checkable half of this: every file path and
gtest name a document names in backticks must exist, and one that deliberately does not
yet goes in `scripts/doc-references-allow.txt` with a justification.
The README's Status table is the contract; its capability table is generated from the registry
the CLI dispatches through. Every physics and numerics file carries an author/title/publication
citation and a `WHAT THIS IS NOT` block naming the validity envelope and the direction of the
known error. A model whose error direction is unstated is a model whose user cannot tell
whether it is conservative.

## Where things are

| | |
|---|---|
| `include/galata/`, `src/` | the library — core, model, numerics, trim, linearize, analyze, sim, pipeline, cli |
| `tests/` | five tiers, one label each; see `docs/TESTING.md` |
| `tests/validation/reference/` | published reference values, each file carrying its citation, rights position and transcription method |
| `tools/validation/` | the case registry and the V&V report generator |
| `tools/social/`, `tools/report/` | run emitters — the pole map card and the NT-33A report page are drawn from these |
| `scripts/` | the gates and the generators; every `gen-*.sh` has a `--check` mode that CI runs |
| `docs/adr/` | the decisions, with the alternatives that were rejected and why |

## Regenerating the committed artefacts

Each is generated, committed, and diffed by CI. If you change the model, the classifier or the
margin code, expect several of these to move together.

```bash
scripts/gen-verification.sh build/dev/tools/validation/galata-validation-report   # docs/VERIFICATION.md
scripts/gen-status-table.sh build/dev/src/cli/galata                              # README capability table
scripts/gen-modal-map.sh   build/dev/tools/social/galata-modal-map                # docs/assets/modal-map.json
python3 scripts/gen-social-preview.py                                             # needs rsvg-convert
scripts/gen-report.sh      build/dev/tools/report/galata-report-data              # the NT-33A run record
python3 scripts/gen-report-page.py                                                # docs/reports/nt33a-fc1.html
```

Add `--check` to any of the shell ones to get exactly what CI runs.

## Skills

Longer-form, in `.claude/skills/`:

- **`validating-against-a-published-source`** — the whole ritual, with the two worked examples:
  the case where galata is wrong and the case where the source is.
- **`preserving-determinism`** — what ADR-0004 requires, what the workflow compares, and the
  C++ constructs that break it quietly.
- **`adding-an-aircraft-model`** — the YAML contract key by key, the non-dimensional to
  dimensional path, and what a new model must ship with.
- **`classifying-modes`** — why classification is by eigenvector participation, what breaks
  under frequency ordering, and every place a new mode touches.

## House style

- C++20, 2-space indent, 100 columns, `clang-format` 20.1.8 pinned — CI diffs the formatting.
- Comments say **why**, and name what was ruled out. A `WHAT THIS IS NOT` block is not
  decoration; it is where the model's limits live.
- Conventional commits, one concern each.
- Shell scripts pass `shellcheck --severity=warning`.
