# Fixed-wing validation contract

This example exercises the complete software path for a fixed-wing numerical
validation review:

```sh
galata run examples/fixed-wing-validation-contract/study.yaml
```

It loads the NT-33A through the shared `VehicleModel` adapter, imports a
declared CSV record, cuts estimation and validation windows from that one
record, runs `identify.validate.vehicle`, and evaluates numerical error budgets.
The report should say `verified disjoint` and `Numerical acceptance gate: pass`.

The record is synthetic: it is a trim trajectory generated by the model and
does not come from an aircraft, flight-test instrumentation, or a qualified
test programme. A passing gate here proves that the software wiring and
arithmetic are exercised; it does not prove model fidelity, airworthiness,
certification, or tool qualification. Replace the record and evidence
references with controlled flight-test artifacts before making an engineering
claim.
