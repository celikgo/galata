# Validating against a published source

This is the thing galata is actually for. The physics is ordinary; what is not ordinary is that
every number in the documentation is a number the code produced, checked against a document
whose citation resolves, inside a budget derived before anyone looked at the answer.

The whole ritual is eight steps. Do them in order. Step 3 before step 5 is the one that matters
most, and it is the one people skip.

---

## 1. Pick a reference with a resolvable citation

Author, title, publication, number, date, and something a stranger can follow. Not "a textbook",
not "MATLAB gives", not "the value everyone uses".

`tests/validation/reference/nt33a_fc1.csv` carries the NTRS document ID, the URL, the
**SHA-256 of the exact PDF** the numbers were read from, and this, which is the part worth
copying:

> The NTRS PDF … is a bitonal CCITTFax G4 microfilm scan … with an OCR text layer bolted on.
> That layer is USABLE ONLY FOR PROSE. On every numeric table page it returns garbage …
> NO VALUE IN THIS FILE CAME FROM THE TEXT LAYER. Every number was read visually from the page
> images. A second, independent pass re-downloaded the document, confirmed its SHA-256, and
> re-read twelve of these values from the page images without reference to the first pass.

State the **rights position** too. ADR-0007 governs this: reference values ship in-tree only
when the source's own rights position permits it, and the file says where that position is
printed. CR-2144 prints "Distribution Statement: Unclassified - Unlimited" on its own Report
Documentation Page, and the CSV quotes that line rather than asserting the conclusion.

**A reference nobody can obtain is not a reference.** If the data is traceable only to a
copyrighted source, ship a loader plus instructions, never the data.

## 2. Transcribe into a reference file, never into a test

Reference values live in `tests/validation/reference/*.csv`, one file per source, loaded by
`galata::testing::load_reference` (`tools/validation/reference_table.hpp`). That loader
**refuses a file with no citation header** — an uncited reference table is exactly the thing
charter rule 8 exists to prevent.

Two shapes, both parsed by the same loader:

- **wide** — one row per independent variable, one numeric column per quantity
  (`ussa1976.csv`: altitude down the side, temperature/pressure/density across).
- **long** — one row per quantity, `quantity,value,units,location`
  (`nt33a_fc1.csv`), which is the only sane shape for a heterogeneous set where "wing area" and
  "C_m_alpha" have nothing in common but the document they came from.

Give every row a `location` naming the table, the row and the page: `Table II-7 row LP' p.27`.
A reviewer must be able to open the PDF at that page and see the number.

The same file is read by the tests and by the V&V report generator, through the same parser,
**deliberately** — a report generated by a second, subtly different reader would be a report
about a different set of numbers.

## 3. Derive the error budget BEFORE you look at your result

This is the step that makes the rest honest, and it must happen first. A tolerance chosen after
seeing the answer is not a budget; it is a description of the answer.

The budget has two parts, and both come from the *source's own printing*:

**(a) The published value's own rounding.** A quantity printed to three significant figures
carries half a unit in its last digit. Use the shared function, do not retype the formula:

```cpp
// tools/validation/reference_table.hpp
[[nodiscard]] double printed_precision_tolerance(double printed,
                                                 int significant_figures,
                                                 double units_in_last_place = 0.5);
```

`0.5` is exact agreement — the computed value rounds to the printed one. The allowance is a
parameter rather than a hidden constant *because it is a published claim*:
`docs/VERIFICATION.md` records which cases needed more than 0.5 and by how much. A gate that
silently absorbed that would be hiding the one number a reader of a V&V report actually wants.

**(b) The rounding of the inputs the published value was computed from.** This is the part that
gets forgotten, and on a derived quantity it usually dominates. `tests/validation/test_nt33a_modes.cpp`
builds it by perturbing **each input by half a unit in its own last printed digit, one at a
time**, and summing the worst deviations — first-order and deliberately conservative. The
tolerance is then

```cpp
const double tolerance = c.input_band + half_ulp(c.published, kPrintedFigures);
```

**Take the steps on the values AS PRINTED, in the units the source prints them in.** An earlier
version of that test converted to SI first and took the ULP afterwards, which understated the
uncertainty of every per-foot derivative by the conversion factor of 3.28. `M_u*` is printed
per second-foot; stepping its per-second-metre form is a different and wrong question.

Where a single relative gate is used instead — the seven NT-33A dimensional derivatives — the
number comes from the same reasoning stated in prose, and the README states it:

> The source prints its inputs and outputs to three significant figures, so each value carries
> up to about 0.5% of its own rounding and several combine in every one of these.
> **The gate is 0.5%. The worst observed is 0.26%.**

Note the shape of that sentence. The gate is the budget. The achievement is reported next to it,
and is *not* the gate.

## 4. Set the gate at the budget, not at what you achieved

If the budget is 0.5% and you measure 0.26%, the gate is 0.5%. Tightening it to 0.3% would make
the suite fail on a legitimate libm difference and teach people to re-run it. Loosening it to
1% throws away the ability to detect a real regression.

Record what you measured in a comment or, better, as a generated figure:

```cpp
EXPECT_LT(worst, 0.005);   // "Measured at 0.26% when this was written."
```

## 5. Register the case

`tools/validation/case_registry.cpp` declares every validation case. The struct is seven fields
(`tools/validation/case_registry.hpp`): `id`, `title`, `capabilities`, `reference`, `status`,
`evidence`, `note`.

Six statuses, and the wording of each is the honest position it is meant to express:

| Status | What it asserts |
|---|---|
| `Validated` | Compared against a published reference and agrees within a stated bound. |
| `ValidatedWithCaveat` | Agrees, but only with a caveat the report spells out. |
| `KnownDiscrepancy` | Compared and does **not** agree. The gap is measured, published, and held by a labelled regression lock. |
| `Unvalidated` | Implemented, but no published reference has been compared against. |
| `SelfConsistent` | Cross-checked against an independent implementation, which is not the same as validated. |
| `NotImplemented` | Does not exist yet. |

An honest `Unvalidated` is worth more than a fabricated match. Do not reach for
`SelfConsistent` to make a row look better — it means one specific thing.

`evidence` names the gtest `Suite.Test` and the binary it lives in. Four reconciliation checks
then make the declaration unfalsifiable by hand:

- every case claiming a comparison names a reference and names its evidence;
- every piece of evidence names a test **actually registered** in that binary, so a renamed or
  deleted test breaks the build rather than leaving a fictional citation;
- every capability declaring *implemented and validated* is backed by at least one validating
  case;
- a case marked *not implemented* may not name a capability that exists.

## 6. Put the measurement in the report by NAME, never by value

`docs/VERIFICATION.md` is generated by `tools/validation/report_main.cpp` and regenerated and
diffed by CI. Prose refers to computed values through `{dotted.placeholders}` — `{hand.phugoid_zeta}`,
`{modes.worst_percent}` — substituted from a map built once at render time.

Two guards stand behind that, and both exist because the mistake is so easy:

- An unknown key renders as the literal `{UNRESOLVED:key}` rather than vanishing —
  *"a silently dropped placeholder is a sentence that reads fine and says nothing"* — and
  `scripts/gen-verification.sh` greps for `UNRESOLVED:` and exits **before** the diff.
- The generator scans every case note for a measured value appearing as a **literal** and
  refuses to emit the document: *"case '<id>' hard-codes the value '<v>', which this report
  computes as {<key>}. Use the placeholder."* This catches the specific mistake of running the
  report, seeing a number, and pasting it into a note — which reads identically to using the
  placeholder and stops being true the moment anything changes.

Printed figures are deliberately **coarsened** for cross-platform stability: three significant
figures, and bounds rounded up to the next power of ten as `below 1e-14`. A report printing
`2.56421e-14` on macOS and `2.56418e-14` on Linux would fail its own staleness gate on every
push.

Then regenerate and commit:

```bash
scripts/gen-verification.sh build/dev/tools/validation/galata-validation-report
scripts/gen-verification.sh build/dev/tools/validation/galata-validation-report --check   # what CI runs
```

## 7. When a deviation exceeds the budget: localise it, and leave it listed

**Never widen the gate.** The move is: isolate the disagreement to the smallest thing that
carries it, write down what was ruled out, record it as `KnownDiscrepancy`, and hold it at its
measured size with a **labelled regression lock**.

A regression lock is not a validation, and it says so in its own name and in a comment above it,
because its bound comes from galata's current output rather than from a published value — which
is exactly what charter rule 8 forbids doing silently.

Make the lock **two-sided**. It should fail when the agreement *improves* as well as when it
degrades, so a future fix is loud instead of silent, and the intended response to that failure
is to replace the lock with a validation — not to loosen the bound.

## 8. Worked example A — where galata is wrong

**The phugoid damping ratio, `Nt33aHandAssembled.PhugoidDampingDiscrepancyDoesNotGrow`.**

A state matrix assembled **by hand** from CR-2144's *dimensional* derivatives gives a phugoid
damping ratio 2.04% below the published value, while the full non-dimensional chain reproduces
it to 0.05%. Two routes to the same published mode from the same report, and they disagree.

What the ritual did with that:

1. **The budget was checked first, and the gap did not fit it.** The published ζ = 0.0948 and
   ω_n = 0.172 are three significant figures, so the published real part carries ±5.6 × 10⁻⁵.
   The observed gap is 6.1× that band. Then all 2¹⁰ corners of the ten inputs' own rounding were
   enumerated: ζ ∈ [0.092521, 0.093219]. **The published value is not reachable** — the most
   favourable corner still falls 1.67% short.

2. **Everything cheap was ruled out, in writing.** A units error in the per-foot scaling (ruled
   out by ω_n, which already agrees to 0.05% and which any scaling error destroys — omitting the
   scaling moves it −21%, applying it twice +10.5%). A transcription error (no single input can
   be moved to close the gap while leaving ω_n where it is; and galata's own chain, which never
   reads that table, corroborates the two sensitive inputs to 0.12% and 0.36% by a route sharing
   no arithmetic). The report printing a reduced-order approximation (four of them were
   evaluated; none lands on 0.0948, and the report's ω_n is the exact quartic root).

3. **Then it was localised to one matrix entry.** Substituting the chain's value for the hand
   assembly's entries **one at a time**: `A(3,4) = M_ẇ·(−g sin θ)/(1 − Z_ẇ)` carries **98.8%** of
   the gap. Zeroing that single term and changing nothing else brings all four longitudinal
   quantities inside the source's own printing precision.

4. **And the physics was named.** That term arises from closing Appendix C's descriptor form by
   substituting the *whole* ẇ equation, gravity included, into `M_ẇ ẇ`. It cannot physically
   exist: `M_ẇ` multiplies the rate of change of aerodynamic incidence, and gravity acts at the
   centre of gravity and produces no moment about it. The chain computes exactly zero there —
   −1.5 × 10⁻¹⁸ — and not by accident.

5. **The hand assembly was left alone anyway.** This is the part to understand. Its value is
   that it is a *literal* reading of the report, independent of galata's own modelling opinions.
   Corrected to agree with the chain, it stops being an independent check and becomes a second
   implementation of the same opinion — and the entry-by-entry comparison that localised this
   discrepancy would no longer be able to find the next one.

The row stays `KnownDiscrepancy`. `docs/notes/phugoid-damping.md` carries the investigation,
including what would settle it: the report's own printed quartic coefficients, or a second
flight condition with γ ≠ 0, since the artefact scales with sin θ and the rival hypothesis does
not. **A hypothesis that predicts the right number is worth more than one tuned to it** — the
fitted `X_q` explanation closes the gap exactly and was rejected for exactly that reason.

## 9. Worked example B — where the source is wrong

**The disk-margin critical frequency,
`DiskMarginSeiler2020.PublishedCriticalFrequencyDisagreesWithItsOwnPublishedPerturbation`.**

Seiler, Packard & Gahinet (2020) print, for their worked example, a critical frequency
ω₀ = 1.94 rad/s together with δ₀ and f₀ — and δ₀ and f₀ are *by construction* evaluated at ω₀.
Neither is reproduced there. Both are reproduced near 1.955 rad/s, which is where the peak
actually is, and 1.955 is what galata reports.

The paper is internally inconsistent. What the ritual did:

1. **The inconsistency was demonstrated from the paper's own numbers**, not asserted. The test
   reconstructs δ(ω) = 1/(S(jω) − ½) from the paper's own loop and evaluates it at the paper's
   own printed frequency.

2. **It was isolated into its own test** rather than absorbed by a loose tolerance in the
   comparison test next to it. The ordinary comparison still passes because the reference file
   grants the critical frequency an explicit, written-down `units_in_last_place` allowance — an
   allowance that lives *in the reference file, in a column, per quantity*, so it is visible
   rather than hidden inside an assertion.

3. **The assertion is deliberately inverted.** It asserts that the paper's printed ω₀ does
   **not** reproduce its printed δ₀, with a message that reads:

   > the paper's printed omega_0 now reproduces its printed delta_0; the recorded discrepancy no
   > longer holds and docs/VERIFICATION.md must be revisited

   *"This test asserts the inconsistency, so that if a future reading of the paper resolves it,
   this test fails and the finding gets revisited."* A finding recorded only in prose rots. A
   finding recorded as a failing-on-change assertion cannot.

4. **The registry says whose problem it is.** The note opens: *"The discrepancy is in the
   SOURCE, not in galata."*

5. **The rest of the paper is still gated, harder.** The strongest disk-margin check is not a
   number comparison at all: it closes the loop with the constructed boundary perturbation and
   requires |1 + f₀·L(jω₀)| < 1e-9 and ||δ₀| − α| < 1e-12. That holds only if α, ω₀, δ₀ and f₀
   are all right *together* — a checkable claim about the loop rather than a restatement of the
   formula.

**The two examples are the same discipline pointed in opposite directions.** In A the budget
said galata was wrong and the answer was to localise, not to widen. In B the budget said the
source was wrong and the answer was to assert it, not to quietly match it.

## Checklist

- [ ] The citation resolves, and the file records the rights position and the transcription method.
- [ ] Reference values are in `tests/validation/reference/`, with a `location` per row.
- [ ] The budget was written down **before** the result was looked at, and includes the inputs'
      rounding as well as the published value's.
- [ ] The gate equals the budget. The achievement is reported beside it, not as it.
- [ ] The case is registered with a status that is the honest one, and evidence naming a real test.
- [ ] No figure about galata's own behaviour is typed into any document — `{placeholder}` only.
- [ ] `scripts/gen-verification.sh … --check` passes, and the regenerated report is committed.
- [ ] Any deviation over budget is localised, published, and held by a two-sided labelled lock —
      not absorbed.

## Never

- Widen a gate to make a number pass.
- Choose a tolerance after seeing the result.
- Take a reference value from the implementation, or from a tool's output, and call it published.
- Remove or relax `Nt33aHandAssembled.PhugoidDampingDiscrepancyDoesNotGrow` or
  `DiskMarginSeiler2020.PublishedCriticalFrequencyDisagreesWithItsOwnPublishedPerturbation`.
- Delete a `KnownDiscrepancy` row because it is embarrassing. It is the most valuable row in the
  table: it is the one nobody could have faked.
